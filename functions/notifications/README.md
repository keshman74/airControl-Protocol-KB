# Звуковые уведомления и восстановление воспроизведения

Каноническая межпроектная сводка; исходные испытания сохранены. Использующие проекты: [airALARM](../../projects/airALARM/README.md), [airControl](../../projects/airControl/README.md), [airKNOB](../../projects/airKNOB/README.md), [KNX Gate](../../projects/knx-gate/README.md). Последние три — возможность повторного использования, не утверждение реализации.

| Устройство/метод | Подтверждённый результат | Что не доказано |
|---|---|---|
| A31 Rakoit 4.6.415156 `PromptEnable`, HTTP `playPromptUrl:<MP3>` | MP3 слышен; радио автоматически возвращается в тестах 13–17 октября | Все источники, форматы, многозонность, длительная стабильность |
| A31 `playPromptUrl:<MP3>%20<N>` | При 10/50 различался уровень; матрица при master 50/80 сохранена | Абсолютная акустическая независимость от master; полный диапазон |
| A31 v0.1.27 временный master + restore | Выбранная громкость и возврат работают; радио около 2 s до/после звучало громче | Избавление от утечки в этом варианте |
| A31 v0.1.28 pause → master → prompt → restore → resume | Позднее в том же отчёте явно обозначен как user hardware-verified baseline | Точные интервалы утечки после исправления, все режимы, отказ/перезагрузка и чужой volume change |
| A33 ACS2 HTTPS 8443 | `prompttone:Enable`, download WAV (200 OK, повтор 400 Exist), play WAV :10 слышен, радио возвращалось | Весь диапазон 10–100, все источники и прошивки |
| A31 `setPlayerCmd:play:<WAV>` | Запускает WAV, прерывает радио без восстановления в данном тесте | Не использовать как эквивалент Prompt |

Источники: [аппаратные команды и отрицательные тесты](../../docs/airALARM-verified-commands-2026-10-10.md), [эволюция решения и регрессия](../../docs/airALARM-A31-volume-path-2026-10-20.md).

## Отдельная громкость — три разных утверждения

1. Software gain smplayer меняет амплитуду Prompt. Подтверждение влияния не доказывает обход downstream master/mute.
2. Временный master с восстановлением удовлетворяет выбранному практическому требованию пользователя. Он меняет зону и может конфликтовать с другим контроллером.
3. Физически независимый выход с постоянной акустической громкостью остаётся **EXPERIMENTAL / UNSOLVED**. Q16-модель и StartupMusic formula не являются его аппаратной проверкой.

[Статический RE](../../docs/airALARM-A31-prompt-reverse-engineering-2026-10-17.md) и [live V2](../../docs/airALARM-A31-live-audio-v2-2026-10-20.md) описывают разные виды доказательств. V1 пустые grep-разделы invalid; V2 заменяет только их. PromptCodec — счётчик; 0x3C8 — M_MODE, 0x3BC — volume. Слово CONFIRMED в заголовках статического разбора означает подтверждённый разбор бинарника, не акустический эффект.

## Сохранить при переносе

Снимок старого master до записи; per-zone serialization; сохранение pending restore до изменения; проверка восстановления; ограниченные retry; отсутствие перекрытия уведомлений. Не считать таймер фактическим концом MP3. Согласовать политику ручного изменения громкости другим контроллером во время сообщения: восстановление старого значения может затереть новое. [Открытые тесты](../../KB_CONFLICTS.md).

## Идентификаторы сопоставленных испытаний

- `TEST-A31-PROMPT-SOFTWARE-GAIN` — матрица субъективного gain, CONFIRMED только её результат.
- `TEST-A31-PROMPT-MASTER-RESTORE` — временный master, восстановление и наблюдавшаяся утечка радио.
- `TEST-A31-PROMPT-PHYSICAL-INDEPENDENCE` — EXPERIMENTAL, цель пока не решена.
- `TEST-A31-LIVE-AUDIO-V1-FILTERS` — SUPERSEDED только invalid grep-E sections, successor live V2.

Эти audit IDs впервые именуют уже описанные выше наблюдения, не создают новые аппаратные испытания. Первичные источники и точные границы — в ссылках выше и [контекстных решениях](../../registry/KB_DECISIONS.json).

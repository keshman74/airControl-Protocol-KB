# airControl KB — аудит согласованности (22 октября 2026)

Статус: **первый проход / обнаруженные риски**, не полный семантический аудит. Проверено дерево `main` (235 объектов), выборочно прочитаны исходные документы. **Никакие старые доказательства, команды или реестры не удалены и не переписаны.**

## Выявленные вопросы

1. **Перекрытие диапазонов CSV**: `registry/records/215-220.csv` и `registry/records/215-221.csv` имеют пересекающиеся номера в именах, но содержат *разные* семейства записей (TCP :8819 и A33M presets). Не считать эти файлы эквивалентами и не удалять один по имени. Нужна проверка уникальности ID, источников агрегирования и ссылок.
2. **Дублирующиеся представления функций**: `functions/source/COMMANDS.md` и `functions/sources/COMMANDS.md` содержат общие команды A31 и A33, причём второй файл включает дополнительные режимы и UPnP. Аналогичные пары по названиям есть у `online-service(s)`, `preset(s)`. Нужен один канонический view и ссылки-алиасы, **без потери дополнительных сведений**.
3. **airALARM A31 live audio V1/V2**: `docs/airALARM-A31-live-audio-2026-10-20.md` фиксирует, что удалённый `grep -E` не поддерживался BusyBox 1.12.1, поэтому пустые результаты отдельных разделов **не являются отрицательным доказательством**. `docs/airALARM-A31-live-audio-v2-2026-10-20.md` описывает исправленную методику и реально заполненные данные. Сохранить оба отчёта, явно ссылаться на V2 для этих разделов.
4. **airALARM handoff**: `docs/airALARM_PROJECT_HANDOFF.md` — предварительная реконструкция; ZIP 1.4 не проверен. Не повышать статус гипотез до CONFIRMED.
5. **Разделение статусов**: в KB встречаются `CONFIRMED`, `DOCUMENTED`, `EXPERIMENTAL` и составные статусы `APK-VERIFIED / NOT-HW-VERIFIED`. Нормализация должна сохранять **тип источника** и **отдельно аппаратную проверку**.

## Политика разрешения конфликтов

- Новая запись **не автоматически истиннее старой**: сравнивать модель устройства, версию прошивки, интерфейс, входные параметры, воспроизводимость и источник.
- Подтверждённое на железе сильнее гипотезы для **того же самого контекста**; документация может относиться к другой версии устройства.
- Исправленные тесты помечать `SUPERSEDED_BY` со ссылкой на новый тест; старые файлы оставлять для воспроизводимости.
- Для одинаковых команд с разными исходами сохранять оба теста и контекст; не смешивать A31/A97/A98/A33.
- Для каждой коллизии вести решение: `record ID → конфликтующие источники → контекст → решение → ссылка на доказательство`.
- Прежде чем менять канонические реестры, проверить весь `registry/records/*.csv` по ID, пересечениям и содержимому, а также все ссылки из `INDEX.md`, `CHATS.md`, `registry/`, `devices/`, `protocols/`, `functions/`.

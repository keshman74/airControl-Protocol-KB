## Method

1. REA inspect_android_package(summary) established package identity and engine version. search_android_classes with empty query returned 12,853 top-level rows, complete within that provider inventory (Evidence `ev_73ee361e2a79d5b82493e246340dcf5e9cfc4f12c8ce3c09bbaef9f43422a44c`).
2. Supplemental dexlib2 instruction scanning from the same JADX MCP JAR enumerated const-string references across classes.dex, classes2.dex and classes3.dex. Original class/method descriptors and instruction code-unit offsets were retained locally and selected command anchors published in the CSV. This catches literal instructions, not every constructed command or encoded field value.
3. A separate all-DEX string-pool search for standalone A97/R328 tokens found no A97, but ALLWINNER-R328 in classes2.dex. This corrected the narrower early class-name search. No absence claim extends to native code, resources, reflection or dynamically downloaded content.
4. Focused JADX API decompilation used the same JAR, one thread, 4 GiB heap, resources skipped, method/anonymous-class inlining disabled. Target code was never loaded into an Android runtime or executed. Generated names may be aliases; original descriptors in the CSV are the stable selectors for this APK.
5. REA independently returned complete isA98, transport E, shutdown Y and multiroom classifier d methods, plus complete smali fallback for the R328-specific service.l.l method. Complete selected records are in the accompanying JSON. Some local Java output contains decompiler warnings; legacy auth selection was checked against smali, and unresolved paths are stated explicitly.
6. Repository base was read from GitHub before adding this evidence. Existing hardware negatives, command IDs and historical CSV shards were preserved. No new hardware confirmation is claimed.

# Chat-to-KB workflow

Research chats are active evidence sources for airControl-Protocol-KB.

## Mandatory update sequence
**discover/test → canonical ID → canonical device/protocol/function/service update → evidence artifact → CHAT link → status update**

Do not leave a command, response, behavior rule or protocol detail only inside a chat audit.

## Hardware confirmation
A documented command becomes CONFIRMED only when evidence contains a real device request/response or equivalent packet/capture proving the behavior. Application implementation alone is IMPLEMENTED, not hardware confirmation.
